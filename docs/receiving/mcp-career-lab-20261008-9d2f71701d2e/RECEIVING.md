## Explicit interface decisions

- HTTP refusals are unsuccessful MCP tool results. Their text preserves the owner's exact `uma-sim API returned HTTP <status>: <raw body>` contract; an empty body omits the colon/body. JSON, malformed JSON, Unicode, whitespace and empty error bodies remain diagnostic text. Failed resource reads remain RPC errors, and a failed mutation is never automatically retried.
- Request IDs are strings or JavaScript safe integers. The bridge refuses null, fractional, nonfinite and unsafe numeric IDs with `-32600` and `id: null`, before dispatch. Use string IDs outside the safe integer range. Only an omitted ID is a notification. The receiving claim is bounded by the explicit tested input contract; it is not a claim of unrestricted protocol conformance.
- Successful JSON tool payloads retain legacy JSON serialization, including strings. Only the new Markdown report returns literal text; JSON report format retains JSON serialization. This follows the feature owner's [explicit compatibility preference](https://github.com/Jacob-Met/uma-sim/pull/68#issuecomment-6056556689).
- The career-lab owner's advertised strict schemas remain in effect: unknown fields, empty ambiguous run targets, invalid nested overrides, string overwrite flags, and out-of-range integers are refused. Seed zero remains accepted. Speed/multiplier zero and previously ignored extra properties are rejected by the career-lab schema. The older error-owner positive ID/default tests now use accepted schema values and safe integer extrema; this narrowing is explicit and remains a receiving-owner integration decision.
- [Issue #63](https://github.com/Jacob-Met/uma-sim/issues/63) still owns the Rust/browser empty-target correction. Current ambiguous read/action/save/load endpoints are protected by pre-request empty-target refusals. Existing safe start, activate and source-fork semantics remain unchanged. Content loading affects the shared catalog for every session.

## Repeat the receiving checks

Use the repository's existing commands and helpers:

```sh
node --test packages/uma-sim-mcp/tests/*.test.mjs
cargo build --locked -p uma-sim-core --bin uma-sim-api
UMA_SIM_TEST_API_BIN="$PWD/target/debug/uma-sim-api" \
  node --test --test-reporter=tap packages/uma-sim-mcp/tests/*.test.mjs
```

The dependency-free MCP job executes the protocol/HTTP tests. Native tests skip only when `UMA_SIM_TEST_API_BIN` is unset; a configured invalid binary fails.
